# Learned injection detector

Agent Warden's regex scanner is the layer an attacker beats first: it misses politely worded payloads and wrongly flags benign emails that merely sound like instructions. This folder trains a small multilingual classifier to replace it, compares it with four alternatives on the same data, and serves it to the TypeScript firewall as the `ml` scan layer.

## Results

Full tables: [`results/DETECTOR.md`](../results/DETECTOR.md). Threshold 0.5.

| Detector | Public test F1 | Held-out technique recall | Hard-negative FPR | Agent Warden recall | CPU latency |
|---|---|---|---|---|---|
| Agent Warden regex | 50.7% | 77.7% | 34.8% | 94.2% | – |
| TF-IDF + logistic regression | 92.8% | 58.7% | **8.0%** | 76.9% | <1 ms |
| Multilingual MiniLM + LR | 85.4% | 69.3% | 22.2% | 82.7% | 6 ms |
| ProtectAI DeBERTa v2 (off the shelf) | 81.1% | 44.0% | 23.2% | 72.1% | 78 ms |
| **Fine-tuned multilingual DistilBERT (ours)** | **95.3%** | **81.0%** | 15.0% | **94.2%** | 18 ms |

- **Ours is best or tied on every recall column** and generalises best to the four attack techniques it never saw in training. The English-only ProtectAI model, strong on public benchmarks, catches 7.7% of Indonesian "official notice" payloads.
- **False positives are the open problem.** 15% of hard negatives (benign emails such as "abaikan email sebelumnya, ruangannya pindah") are flagged, and raising the threshold barely helps (9% at 0.999): the model is confidently wrong. More varied benign training data is the fix, not a threshold.
- **In the agent** (worst-case scripted model, same 104 attacks): the learned layer alone lets 11.5% of attacks through versus 14.4% for regex; the full stack with it stays at **0/104**. It costs one benign task: a confidential offer letter ("mohon tidak disebarkan") reads like a concealment instruction.

## Design choices that mattered

- **Leak-free splits.** Carrier email templates, attacker goals and benign trap sentences are each split between train and test; 0 test texts appear in training. Four techniques (base64, forged turns, impersonation, authority) are held out entirely.
- **Frozen vocabulary embeddings.** The multilingual vocabulary is ~92M of DistilBERT's 135M parameters. Fine-tuning all of it pushed a 16 GB laptop into 9 GB of swap (10+ minutes per 50 steps); freezing it trains 43.5M parameters in under 6 minutes with no visible loss in validation accuracy (99.6%).
- **One line as the unit of context.** Sentence-by-sentence classification flagged a teammate's "kamu bagian deployment ya" (0.98 alone, 0.0003 inside its email). Classifying a whole multi-item tool output had the opposite problem: one injected deadline was diluted by the others. The layer classifies each line (an email body, a listing item), then localises flagged lines to sentences.
- **Fail closed.** If the detector service is unreachable, untrusted text is withheld rather than passed through.

## Run it

```bash
cd detector
uv sync
uv run python data.py      # build datasets (downloads two Apache-2.0 datasets)
uv run python train.py     # fine-tune → model/ (~6 min on an M-series Mac)
uv run python bench.py     # compare 5 detectors → ../results/DETECTOR.md
uv run python sweep.py     # threshold operating points
uv run uvicorn serve:app --port 8765
# in the repo root:
npm run eval -- --model scripted --defenses ml,full_ml
```

Data: [deepset/prompt-injections](https://huggingface.co/datasets/deepset/prompt-injections) and [jackhhao/jailbreak-classification](https://huggingface.co/datasets/jackhhao/jailbreak-classification) (both Apache-2.0), plus synthetic English/Indonesian emails generated by `data.py`. Base model: [distilbert-base-multilingual-cased](https://huggingface.co/distilbert/distilbert-base-multilingual-cased) (Apache-2.0). Trained weights are not committed; `train.py` reproduces them (seeded).
